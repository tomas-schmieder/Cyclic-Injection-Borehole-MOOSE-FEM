# Corrections to the submitted report

`docs/report.pdf` is the report as submitted in May 2025 and has not been altered.
Reconstructing this repository in July 2026 surfaced errors in it. They are listed here so
that anyone reading the PDF on its own can find them.

---

## 1. The "very high karst" figure shows k = 1×10⁻³ m², not 1×10⁻⁷ m²

**Severity: affects a stated result.**

Two input files wrote to the same output directory:

| Input file | Permeability | `file_base` |
|---|---|---|
| `cycle1_very_high_karst.i` | 1×10⁻⁷ m² | `CYCLE-FILES-very_high_karst/output` |
| `cycle1_highest.i` | 1×10⁻³ m² | `CYCLE-FILES-very_high_karst/output` |

`runall.sh` ran them in that order, so `cycle1_highest.i` overwrote the karst results. The
figures and table entries labelled "very high karst" or "1e-7" were then generated from
whatever was left in that directory.

Both cases were re-run separately in July 2026 and compared against the archived output.
The archived sampler data is **bit-identical** to the k = 1×10⁻³ run (max absolute
difference 0.0 Pa across the pressure profile) and **differs** from the k = 1×10⁻⁷ run
(max absolute difference 4.0×10⁻⁷ Pa). The archived results are therefore the 1×10⁻³ case.

**What this affects in the report:**

- the per-case figure captioned `plot_very_high_karst.png`
- the "1e-7" curve on both `comparison_pressure_t500.png` and
  `comparison_displacement_t500.png`
- any discussion of karst-permeability behaviour that draws on those figures

**Corrected figures** are in `figures/`: `plot_very_high_karst.png` is now the genuine
k = 1×10⁻⁷ case, and `plot_extreme_1e-3.png` is the k = 1×10⁻³ case that was previously
mislabelled. The comparison plots have been regenerated with the two separated.

Note that k = 1×10⁻³ m² is not a physical soil permeability — it is roughly ten orders of
magnitude above karst — so the mislabelled figure was showing an essentially
instantaneous-equilibration limit rather than karst behaviour.

## 2. The `anisotropic_x_high` case did not run from the batch script

**Severity: process error, results unaffected.**

`runall.sh` contained a typo:

```bash
  "cycle1_anisotropic_x_high.i"ch
```

The trailing `ch` made the shell expand this to `cycle1_anisotropic_x_high.ich`, which does
not exist, so that case was skipped whenever the script was used. The case was evidently
run by hand at some point — output exists and the figure is correct — but it was not part
of the automated sweep. `scripts/run_all.sh` fixes this.

## 3. `permeability_summary.csv` in the results is empty

**Severity: missing deliverable.**

The notebook cell that wrote the summary table iterated over `cycle_folders`, which had
been reset to `[]` in that cell. The file it produced contains a single newline. The
companion `permeability_summary0.5.csv` is non-empty but contains **one** row — the
`dt0.5` case only — rather than a row per case.

The original single-row `permeability_summary0.5.csv` is preserved unchanged in
`figures/`. The empty file is not carried over. `figures/permeability_summary.csv` is a
complete table across all twelve cases, generated by `scripts/postprocess.py`; its row for
the dt = 0.05 s case reproduces the original's numbers exactly (max pressure
1335587.1563765 Pa), which is the check that the rewritten pipeline matches the original
analysis.

## 4. The `CYCLE-FILES-dt0.5` directory holds the dt = 0.05 s run

**Severity: labelling.**

The directory named `dt0.5` contains 20,000 timesteps over a 1000 s simulation, which is
dt = 0.05 s, and the directory named `very_low_clay` contains 2000 timesteps, which is
dt = 0.5 s. The names are the wrong way round relative to what they contain. Anywhere the
report refers to a "dt0.5" case as the refined run, it means the dt = 0.05 s run.

In this repository the cases are named `very_low_clay` (dt = 0.5 s) and
`very_low_clay_dt0.05` (dt = 0.05 s, with `nl_abs_tol` tightened to 1×10⁻⁷ and
`nl_max_its` raised to 200).

## 5. `CYCLE-FILES-isotropic_1e-13` and `CYCLE-FILES-medium_sand` are the same run

**Severity: duplication, no impact on results.**

The sampler CSVs in the two directories are identical; `isotropic_1e-13` was an earlier
name for what became `medium_sand` (k = 1×10⁻¹³ m² isotropic). If both
`plot_isotropic_1e-13.png` and `plot_medium_sand.png` appear in the report, they show the
same simulation. Only `plot_medium_sand.png` is kept here.

## 6. Sampler region names are inconsistent between fields

**Severity: naming only, data correct.**

The `LineValueSampler` blocks cover three radial windows, but pore pressure and
displacement use different names for two of them:

| x range | pore pressure label | displacement label |
|---|---|---|
| 0 – 13.5 m | `left` | `left` |
| 16.5 – 33.5 m | `right` | `middle` |
| 36.5 – 50 m | `middle` | `right` |

The `x` coordinates written into each CSV are correct, and the analysis groups by `x`
rather than by region, so no plotted result is wrong. But the `region` column should not
be used to match a pressure sample to a displacement sample.
